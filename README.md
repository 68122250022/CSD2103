## 1. คำอธิบายแนวคิดของอัลกอริทึม
โจทย์กำหนดให้ออกแบบอย่างน้อย 2 อัลกอริทึม:

อัลกอริทึมที่ 1 (Recursive Algorithm): แนวคิดคือการดึงตัวอักษรตัวสุดท้ายของสตริงออกมา แล้วนำไปต่อกับผลลัพธ์ที่ได้จากการเรียกซ้ำ (Recursive call) ด้วยสตริงส่วนที่เหลือที่ถูกตัดตัวสุดท้ายออกไปแล้ว

Base Case: เมื่อสตริงว่างเปล่า (Empty) หรือมีค่าเป็น null ให้คืนค่าสตริงนั้นกลับไปโดยไม่ต้องทำอะไรต่อ เพื่อหยุดการทำงานแบบเวียนเกิดและป้องกันโปรแกรมหยุดทำงานผิดปกติ

Recursive Case: เมื่อความยาวสตริงมากกว่า 0 จะทำการแยกตัวอักษรสุดท้าย s.charAt(s.length() - 1) มาเชื่อมต่อกับ reverseRecursive(s.substring(0, s.length() - 1))

อัลกอริทึมที่ 2 (Iterative Algorithm): ใช้การวนลูปอ่านข้อความจากตำแหน่งดัชนี (Index) สุดท้ายย้อนกลับไปยังตำแหน่งแรกสุด แล้วนำตัวอักษรมาประกอบกัน ในการนำไปใช้งานจริงจะมีการปรับปรุงโดยใช้ StringBuilder เพื่อหลีกเลี่ยงปัญหาด้านประสิทธิภาพจากการต่อสตริงด้วยเครื่องหมาย +

## 5. การวิเคราะห์ Time Complexity

จำนวนครั้งที่ประมวลผลตัวอักษร: ทุกอัลกอริทึมต้องเข้าถึงตัวอักษรทุกตัวจำนวน 1 ครั้งเพื่อนำมาจัดเรียงใหม่

Recursive Algorithm: มี Time Complexity เป็น O(N^2) (ในภาษา Java) เนื่องจากมีการเรียกซ้ำ N รอบ และในแต่ละรอบมีการใช้คำสั่ง substring และเครื่องหมาย + ซึ่งกระบวนการเหล่านี้ใน Java จะต้องทำการคัดลอก (Copy) อาเรย์ตัวอักษรตัวใหม่ขึ้นมาทุกครั้ง ทำให้เกิดภาระงานที่แปรผันตามความยาวสตริง

Iterative Algorithm (แบบใช้ +): มี Time Complexity เป็น O(N^2) เพราะการต่อสตริงด้วย + ในลูป จะสร้างออบเจกต์ String ใหม่ทุกครั้งตามจำนวนรอบ N

Iterative Algorithm (แบบใช้ StringBuilder): มี Time Complexity เป็น O(N) เพราะลูปทำงาน N รอบ และการใช้ .append() จัดการข้อมูลใน Buffer เดิมโดยไม่ต้องสร้างออบเจกต์ใหม่ทุกรอบ ทำให้ใช้เวลาประมวลผลแต่ละรอบคงที่ (Constant time)

## 6. การวิเคราะห์ Space Complexity

Recursive Algorithm: มี Space Complexity เป็น O(N) เนื่องจากต้องใช้พื้นที่ในหน่วยความจำสำหรับการเก็บ Call Stack ลึกลงไปเท่ากับความยาวของสตริง N (หากสตริงยาวมากๆ จะทำให้เกิด StackOverflow)

Iterative Algorithm: มี Space Complexity เป็น O(N) เนื่องจากไม่ว่าจะเป็นการใช้ String หรือ StringBuilder โปรแกรมจะต้องจองพื้นที่หน่วยความจำเพื่อเก็บข้อความผลลัพธ์ที่มีความยาว N เท่ากับข้อความต้นฉบับ แต่จะไม่มีการใช้ Call Stack เพิ่มเติม

## 7. การเปรียบเทียบข้อดีและข้อจำกัดของแต่ละอัลกอริทึม

Recursive Algorithm

ข้อดี : โค้ดสั้น กระชับ สะท้อนแนวคิดการแบ่งปัญหา (Divide and Conquer) ได้ชัดเจน

ข้อจำกัด : ใช้หน่วยความจำ Call Stack สูง เสี่ยงต่อ StackOverflowError เมื่อสตริงยาวมาก (เช่น 10,000 ตัวอักษร)

Iterative (ใช้เครื่องหมาย +)

ข้อดี : เขียนง่ายตามความคุ้นเคย

ข้อจำกัด : ผลกระทบจากการต่อสตริงด้วย + ทำให้สิ้นเปลืองหน่วยความจำและเวลาทำงานช้าลงแบบก้าวกระโดด O(N^2) เมื่อข้อมูลใหญ่ขึ้น

Iterative (ใช้ StringBuilder)

ข้อดี : ความแตกต่างระหว่าง String และ StringBuilder คือมันสามารถปรับเปลี่ยนค่า (Mutable) ได้ใน Buffer เดิม ทำให้ทำงานเร็วกว่าแบบแรกมหาศาลและปลอดภัยจาก Call Stack

ข้อจำกัด : โค้ดอาจดูยาวกว่า Recursive เล็กน้อย

## 8. สรุปว่าอัลกอริทึมใดเหมาะสมกว่าภายใต้เงื่อนไขใด

# ข้อ 2 การตรวจสอบ Palindrome

## 1. คำอธิบายแนวคิดของอัลกอริทึม

ก่อนการตรวจสอบสตริง จะต้องทำความสะอาดข้อความ (Sanitization) โดยตัดช่องว่าง เครื่องหมายวรรคตอน ออกทั้งหมด และแปลงเป็นตัวพิมพ์เล็ก เพื่อรองรับเงื่อนไขเพิ่มเติม (เช่น "A man, a plan, a canal: Panama")

อัลกอริทึมที่ 1: Reverse and Compare (isPalindromeByReverse)
แนวคิดคือการสร้างสตริงย้อนกลับ (Reversed String) ขึ้นมาใหม่ทั้งหมดก่อน จากนั้นจึงนำสตริงใหม่มาเปรียบเทียบกับสตริงเดิมด้วยเมธอด .equals() หากเหมือนกันทุกประการแสดงว่าเป็น Palindrome

อัลกอริทึมที่ 2: Recursive Two-Pointer (isPalindromeRecursive)
แนวคิดคือการใช้ตัวชี้ 2 ตำแหน่ง คือ left (ซ้ายสุด) และ right (ขวาสุด) เปรียบเทียบตัวอักษรคู่ดังกล่าว หากพบว่าไม่เท่ากันจะสรุปทันทีว่า ไม่ใช่ Palindrome แต่ถ้าเท่ากันจะทำการเรียกเมธอดตัวเองซ้ำ (Recursive) โดยขยับตัวชี้เข้าหากัน (left + 1, right - 1)

  Base Case 1: left >= right คืนค่า true (ตรวจสอบครบทุกคู่แล้ว ตัวชี้มาชนกันหรือเหลื่อมกัน แสดงว่าเป็น Palindrome)

  Base Case 2: s.charAt(left) != s.charAt(right) คืนค่า false (พบตัวอักษรไม่ตรงกัน หยุดการทำงานทันที)

  Recursive Case: isPalindromeRecursive(s, left + 1, right - 1) (ตัวอักษรตรงกัน ให้ส่งคู่อื่นเข้าไปตรวจสอบต่อ)

## 5. การวิเคราะห์ Time Complexity

Algorithm 1: Reverse and Compare

  Best-case Time Complexity: O(N)
  
    เหตุผล : ไม่ว่าสตริงนั้นจะผิดตั้งแต่อักษรคู่แรกหรือไม่ อัลกอริทึมนี้ต้องเสียเวลาวนลูปเพื่อย้อนสตริงทั้งหมด N ตัวอักษรให้เสร็จสิ้นก่อนเสมอ จึงจะเริ่มเปรียบเทียบได้

  Worst-case Time Complexity: O(N)
  
    เหตุผล: ต้องวนลูปกลับสตริง N ตัวอักษร และเปรียบเทียบสตริงอีก N ตัวอักษร

Algorithm 2: Recursive Two-Pointer

  Best-case Time Complexity: O(1)

    เหตุผล: ในกรณีที่ตัวอักษรคู่แรกสุดไม่ตรงกัน (เช่น คำว่า "algorithm" เปรียบเทียบ 'a' กับ 'm') โปรแกรมจะเข้าเงื่อนไข Base Case 2 และ คืนค่า false ทันที โดยไม่มีการเรียกซ้ำอีก

  Worst-case Time Complexity: O(N)

    เหตุผล: กรณีที่เป็น Palindrome หรือตัวอักษรที่ไม่ตรงกันไปไม่อยู่ตรงจุดศูนย์กลาง โปรแกรมจะต้องทำการเรียกซ้ำเพื่อเปรียบเทียบจนครบ N/2 คู่

## 6. การวิเคราะห์ Space Complexity

Algorithm 1: Reverse and Compare: O(N)

  เหตุผล: ต้องจองหน่วยความจำเพื่อสร้างออบเจกต์สตริงชุดใหม่ (Reversed String) ขนาดความยาว N เท่ากับสตริงเดิม

Algorithm 2: Recursive Two-Pointer: O(N) (Worst-case) / O(1) (Best-case)
  
  เหตุผล: ในกรณีแย่สุดจะเกิด Call Stack ลึกลงไป N/2 ชั้น ตามจำนวนครั้งของการเวียนเกิด ส่วนกรณีที่ดีที่สุด (เจอตัวอักษรไม่ตรงกันในคู่แรก) จะใช้ Call Stack เพียง O(1)

## 7. การเปรียบเทียบเชิงวิเคราะห์ตามโจทย์

Algorithm 1: Reverse & Compare

  กรณีที่เป็น Palindrome : วนลูปอ่านตัวอักษร N ครั้ง และเปรียบเทียบ N ครั้ง
  
  กรณีที่ตัวอักษรคู่แรกไม่ตรงกัน : ช้ากว่า เพราะต้องสร้างสตริงย้อนกลับจนครบ N ตัวอักษรก่อน ถึงจะเริ่มเปรียบเทียบได้
  
  ความสามารถในการหยุดทำงานก่อนครบ (Early Exit) : ทำไม่ได้ (No Early Exit) ต้องทำกระบวนการวนกลับให้เสร็จก่อน

Algorithm 2: Recursive Two-Pointer

  กรณีที่เป็น Palindrome : เรียกเมธอดซ้ำ N/2 ครั้ง เพื่อตรวจสอบทีละคู่จนถึงจุดศูนย์กลาง
  
  กรณีที่ตัวอักษรคู่แรกไม่ตรงกัน : เร็วมาก เพราะเปรียบเทียบคู่แรกแล้วคืนค่า false ออกไปทันที
  
  ความสามารถในการหยุดทำงานก่อนครบ (Early Exit) : ทำได้ (Has Early Exit) หยุดการทำงานทันทีที่พบอักษรไม่เข้าคู่กัน

## 8. สรุปว่าอัลกอริทึมใดเหมาะสมกว่าภายใต้เงื่อนไขใด

  Recursive Two-Pointer มีความเหมาะสมกว่ามากในกรณีที่ ข้อมูลส่วนใหญ่ไม่ใช่ Palindrome หรือต้องการ ความเร็วในการคัดกรอง (Early Exit) เนื่องจากสามารถสรุปผลลัพธ์ว่าเป็น false ได้ตั้งแต่การเปรียบเทียบคู่แรกๆ โดยไม่ต้องประมวลผลสตริงจนจบ

  Reverse and Compare เหมาะสมสำหรับการเขียนโค้ดเน้นความเรียบง่าย เข้าใจง่าย หรือในกรณีที่ภาษาโปรแกรมนั้นๆ มีฟังก์ชัน Built-in สลับสตริงที่ได้รับการปรับแต่งระดับ Hardware มาแล้ว แต่โดยโครงสร้างอัลกอริทึมทั่วไปจะสิ้นเปลืองหน่วยความจำ O(N) ในการสร้างข้อความชุดใหม่โดยไม่จำเป็น

# ข้อ 3 การเปรียบเทียบจำนวนสระและพยัญชนะ

## 1. คำอธิบายแนวคิดของอัลกอริทึม

เงื่อนไขสำคัญคือการนับเฉพาะตัวอักษรภาษาอังกฤษ (a-z, A-Z) โดยไม่แยกตัวพิมพ์เล็ก-ใหญ่ และ ต้องไม่นับตัวเลข ช่องว่าง หรือเครื่องหมายพิเศษ

  อัลกอริทึมที่ 1: Recursive Counting (hasMoreVowelsRecursive)

    ใช้วิธีเรียกเมธอดซ้ำ โดยใช้เมธอดผู้ช่วย (Helper Method) เพื่อส่งดรรชนี (index) และสะสมตัวนับจำนวนสระ (vowels) กับพยัญชนะ (consonants) ไปยังการทำงานถัดไป

    Base Case: เมื่อ index == s.length() (อ่านข้อความจนครบทุกตัวอักษรแล้ว) ให้คืนผลลัพธ์การเปรียบเทียบ vowels > consonants (ส่งค่า true หรือ false กลับไป)

    Recursive Case: ตรวจสอบตัวอักษร ณ ตำแหน่ง index ปัจจุบัน หากเป็นสระให้บวก vowels เพิ่ม 1 หากเป็นพยัญชนะให้บวก consonants เพิ่ม 1 (หากเป็นช่องว่าง ตัวเลข หรือสัญลักษณ์ ให้ข้ามไป) จากนั้นเรียกเมธอดตัวเองซ้ำโดยส่ง index + 1

  อัลกอริทึมที่ 2: Iterative Counting (hasMoreVowelsIterative)

    ใช้การวนลูป for ตั้งแต่ดรรชนี 0 ถึง s.length() - 1 อ่านตัวอักษรทีละตัว แล้วอัปเดตตัวแปรตัวนับ vowels หรือ consonants ตามประเภทตัวอักษร เมื่อวนลูปจบ คืนค่าผลลัพธ์ vowels > consonants

## 5. การวิเคราะห์ Time Complexity

  Recursive Counting: O(N)

    เหตุผล: เมธอดจะถูกเรียกทำงานซ้ำเท่ากับจำนวนตัวอักษร N ตัว โดยในการทำงานแต่ละชั้นจะเข้าถึงตัวอักษร 1 ตัวเพื่อเช็กเงื่อนไข Constant Time O(1) รวมเวลาทั้งหมดเป็น O(N)

  Iterative Counting: O(N)

    เหตุผล: วนลูป for ทำงานตามความยาวสตริง N รอบ แต่ละรอบประมวลผลตัวอักษร 1 ตัว รวมใช้เวลา O(N)
    
## 6. การวิเคราะห์ Space Complexity

  Recursive Counting: O(N)

    เหตุผล: ต้องใช้พื้นที่ใน Call Stack เพื่อเก็บสถานะของฟังก์ชันลึกลงไปเท่ากับจำนวนตัวอักษร N

  Iterative Counting: O(1)

    เหตุผล: ใช้เพียงตัวแปรชนิด Primitive (int vowels, int consonants, int i) ในการนับจำนวน ไม่มีการจองพื้นที่ในหน่วยความจำเพิ่มตามขนาดข้อมูล N

## 7. งานวิเคราะห์เจาะลึกตามข้อกำหนด

  จำนวน Recursive calls:

    หากข้อความมีความยาว $N$ ตัวอักษร โปรแกรมจะมีการเรียกเมธอดซ้ำทั้งหมด $N + 1$ ครั้ง (เรียกประมวลผลตำแหน่ง 0 ถึง N-1 จำนวน $N$ ครั้ง และเรียกครั้งที่ $N+1$ เมื่อ index == N เพื่อเข้า Base Case และคืนค่าสรุปผล)

  ความเสี่ยงของ StackOverflowError:

    วิธี Recursive มีความเสี่ยงสูงมากที่จะเกิด StackOverflowError เมื่อประมวลผลสตริงที่มีความยาวตั้งแต่ประมาณ 10,000 ตัวอักษรขึ้นไป เนื่องจาก Call Stack มีขนาดจำกัดใน JVM

    วิธี Iterative ไม่มีความเสี่ยง ต่อการเกิด StackOverflowError เนื่องจากใช้โครงสร้างวนลูปใน Frame เดียว

  ขนาดข้อมูลที่เหมาะสมสำหรับแต่ละวิธี:

    Recursive Counting: เหมาะสำหรับข้อมูลขนาดเล็กถึงปานกลาง ($N < 1,000$ ตัวอักษร)
    
    Iterative Counting: เหมาะสำหรับข้อมูลทุกขนาด ตั้งแต่ขนาดเล็กไปจนถึงขนาดใหญ่มาก ($N \ge 10,000$ ตัวอักษรขึ้นไป)

## 8. สรุปความเหมาะสม

Iterative Counting เป็นอัลกอริทึมที่ เหมาะสมกว่าสำหรับการนำไปใช้งานจริง เพราะใช้พื้นที่หน่วยความจำคงที่ ($O(1)$ Space Complexity) และไม่มีความเสี่ยงเรื่องการทำงานล้มเหลวจาก StackOverflowError เมื่อต้องจัดการกับข้อมูลชุดใหญ่

ในขณะที่ Recursive Counting เหมาะสำหรับการศึกษาโครงสร้างการเขียนโปรแกรมแบบเวียนเกิด และการทำความเข้าใจเรื่อง Tail Recursion / State Passing ในการส่งผ่านค่าสะสมผ่านพารามิเตอร์ของฟังก์ชันเท่านั้น

## 1. คำอธิบายแนวคิดของอัลกอริทึม

โจทย์กำหนดให้ออกแบบอย่างน้อย 3 อัลกอริทึมในการจัดกลุ่มให้อารีเรย์มีเลขคู่ขึ้นก่อนเลขคี่:

  อัลกอริทึมที่ 1: Recursive Two-Pointer (rearrangeRecursive)

    ใช้วิธีเวียนเกิดร่วมกับตัวชี้ 2 ตำแหน่ง (left อยู่ซ้ายสุด และ right อยู่ขวาสุด)

    Base Case: เมื่อ left >= right ให้หยุดการทำงาน (ประมวลผลจัดกลุ่มสลับตัวเลขครบทุกตำแหน่งแล้ว)

    Recursive Case:

      ถ้า a[left] เป็นเลขคู่ ให้เลื่อน left ไปทางขวา (left + 1)

      ถ้า a[right] เป็นเลขคี่ ให้เลื่อน right ไปทางซ้าย (right - 1)

      ถ้า a[left] เป็นเลขคี่ และ a[right] เป็นเลขคู่ ให้สลับค่า (Swap) ระหว่างตำแหน่ง left และ right จากนั้นขยับตัวชี้ทั้งสองพร้อมกัน (left + 1, right - 1)

  อัลกอริทึมที่ 2: Iterative Two-Pointer (rearrangeTwoPointer)

    ใช้แนวคิด Two-Pointer เดียวกับวิธีแรก แต่เปลี่ยนจากการเรียกเมธอดซ้ำมาใช้การวนลูป while (left < right) เพื่อเลื่อนตัวชี้และทำการสลับค่าในอาเรย์เดิมทันที (In-place)

  อัลกอริทึมที่ 3: Extra Array (rearrangeExtraArray)

    สร้างอาเรย์ใหม่ที่มีขนาดเท่ากับอาเรย์เดิม วนลูปอ่านอาเรย์ต้นฉบับรอบแรกเพื่อคัดเอาเฉพาะ เลขคู่ ไปใส่ในอาเรย์ใหม่ตามลำดับ จากนั้นวนลูปอ่านรอบที่สองเพื่อนำ เลขคี่ ไปใส่ต่อท้ายในอาเรย์ใหม่

Recursive Two-Pointer เหมาะสมสำหรับการศึกษาทำความเข้าใจกระบวนการทำงานแบบ Divide and Conquer หรือการใช้ตัวชี้คู่ในการเวียนเกิดเท่านั้น ไม่เหมาะสำหรับการนำไปใช้งานจริงกับข้อมูลขนาดใหญ่เนื่องจากสิ้นเปลือง Call Stack

# ข้อ 5 การแบ่งอาร์เรย์ตามค่า k

## 1. คำอธิบายแนวคิดของอัลกอริทึม

โจทย์ต้องการให้จัดเรียงสมาชิกในอาร์เรย์ใหม่โดยแบ่งออกเป็น 2 กลุ่ม คือ กลุ่มที่มีค่าน้อยกว่าหรือเท่ากับ k (\le k) ไว้ด้านหน้า และกลุ่มที่มีค่ามากกว่า k (> k) ไว้ด้านหลัง

  อัลกอริทึมที่ 1: Recursive Partition (partitionRecursive)

    ใช้ตัวชี้ 2 ตำแหน่ง (left อยู่ซ้ายสุด และ right อยู่ขวาสุด) ในการประมวลผลแบบเวียนเกิด

    Base Case: เมื่อ left >= right ให้หยุดการทำงาน

    Recursive Case:

      ขยับ left ไปทางขวาเรื่อยๆ ตราบใดที่ a[left] <= k
      
      ขยับ right ไปทางซ้ายเรื่อยๆ ตราบใดที่ a[right] > k
      
      หากพบว่า left < right (ตัวซ้ายมากกว่า k และตัวขวาน้อยกว่าหรือเท่ากับ k) ให้สลับค่า (Swap) ทั้งสองตำแหน่ง แล้วเรียกตัวเองซ้ำเพื่อประมวลผลช่วงถัดไป (left + 1, right - 1)

 อัลกอริทึมที่ 2: Iterative Partition (partitionIterative)
   
    ใช้แนวคิด สองตัวชี้ (Two Pointers) เช่นเดียวกับวิธีแรก แต่เปลี่ยนเป็นลูป while (left < right) ในการเลื่อนตัวชี้ และทำการสลับตำแหน่งข้อมูลทันทีภายในลูปโดยไม่ต้องใช้ Call Stack

  อัลกอริทึมที่ 3: Sorting-Based Algorithm (partitionBySorting)

    ใช้การเรียงลำดับข้อมูลทั้งอาร์เรย์ก่อน (เช่น การเรียงจากน้อยไปมากด้วย Arrays.sort()) ซึ่งจะทำให้สมาชิกทุกตัวที่ \le k ถูกจัดไปอยู่ด้านหน้าโดยอัตโนมัติ จากนั้นทำ Binary Search หรือ Linear Search ค้นหาตำแหน่งดรรชนีสุดท้ายที่มีค่าน้อยกว่าหรือเท่ากับ k

## 5. การวิเคราะห์ Time Complexity

  Recursive Partition: O(N)
    
    เหตุผล: ตัวชี้ left และ right เลื่อนผ่านสมาชิกแต่ละตัวในอาร์เรย์เพียงครั้งเดียว รวมการประมวลผลทั้งหมดเป็น N ขั้นตอน

  Iterative Partition: O(N)

    เหตุผล: ใช้ลูปเดียวในการสแกนข้อมูลทั้งอาร์เรย์ สมาชิกทุกตัวถูกตรวจสอบเพียงครั้งเดียว

  Sorting-Based Algorithm: O(N \log N)

    เหตุผล: ขั้นตอนการเรียงลำดับด้วย Arrays.sort() ใช้เวลา O(N \log N) ส่วนการสแกนหาตำแหน่งสุดท้ายใช้เวลา O(N) ทำให้เวลาสุทธิขึ้นอยู่กับขั้นตอนการเรียงลำดับ

## 6. การวิเคราะห์ Space Complexity

  Recursive Partition: O(N) (Worst Case)

    เหตุผล: มีการสร้าง Call Stack จากการเรียกฟังก์ชันซ้ำ ลึกลงไปสูงสุด N/2 ชั้น หรือ O(N)

  Iterative Partition: O(1)

    เหตุผล: ใช้ตัวแปรตำแหน่ง left, right และตัวแปรสลับค่าชั่วคราว (temp) ทำให้ใช้พื้นที่คงที่

  Sorting-Based Algorithm: O(\log N) ถึง O(N)

    เหตุผล: ขึ้นอยู่กับอัลกอริทึมการ Sorting ของระบบ (เช่น Dual-Pivot Quicksort ใน Java Primitive Types ใช้พื้นที่ O(\log N) สำหรับ Recursion Stack)

## 7. งานวิเคราะห์เจาะลึกตามโจทย์

เหตุผลที่การเรียงลำดับ (Sorting) อาจทำให้โปรแกรมช้ากว่าที่จำเป็น

โจทย์ต้องการเพียงแค่ "การแบ่งกลุ่ม (Partitioning)" ออกเป็น 2 ฝั่งเท่านั้น ไม่ได้ต้องการให้สมาชิกภายในกลุ่มเดียวกันเรียงลำดับจากน้อยไปมาก

  การใช้ Partitioning (Iterative / Recursive) ทำงานด้วยความเร็ว O(N) (Linear Time)การใช้ Sorting ต้องเสียเวลาทำเกินความจำเป็นในการจัดเรียงสมาชิกภายในกลุ่มทั้งหมด ทำให้ความเร็วตกไปเป็น O(N \log N)

ความสัมพันธ์ของปัญหานี้กับขั้นตอน Partition ใน Quick Sort

ปัญหานี้คือ ตัวอย่างจริงของขั้นตอน Partition ในอัลกอริทึม Quick Sort

  ใน Quick Sort จะเลือกสมาชิกตัวหนึ่งขึ้นมาเป็น Pivot (ในโจทย์ข้อนี้คือค่า $k$)
  
  จากนั้นแบ่งอาร์เรย์ออกเป็น 2 ส่วน: ฝั่งซ้ายมีค่าน้อยกว่าหรือเท่ากับ Pivot และฝั่งขวามีค่ามากกว่า Pivot เพื่อเตรียมนำแต่ละฝั่งไปทำ Quick Sort ในย่อยถัดไป (ระเบียบวิธีที่ใช้นี้สอดคล้องกับ Hoare's Partition Scheme)

การระบุการทำงานแบบ In-place

  Iterative Partition: ทำงานแบบ In-place 100% เพราะแก้ไขข้อมูลในอาร์เรย์เดิมโดยตรงและใช้หน่วยความจำเพิ่มคงที่ (O(1) Auxiliary Space)
  
  Recursive Partition: เป็นการจัดข้อมูลแบบ In-place ในแง่ของข้อมูลอาร์เรย์ (ไม่สร้างอาร์เรย์ใหม่) แต่ ไม่เป็น In-place ทางหน่วยความจำระบบ เนื่องจากต้องใช้ Call Stack O(N)
  
  Sorting-Based Algorithm: ขึ้นอยู่กับอัลกอริทึม Sorting ใน Java Dual-Pivot Quicksort นับว่าเป็น In-place ในแง่อาร์เรย์ แต่ใช้พื้นที่ Stack O(\log N)

## 8. สรุปอัลกอริทึมที่เหมาะสมที่สุด

Iterative Partition เป็นวิธีที่ดีและเหมาะสมที่สุดสำหรับโจทย์ข้อนี้ เนื่องจากทำงานด้วยความเร็วสูงสุด O(N) ใช้หน่วยความจำเพิ่มคงที่ O(1) (In-place) และไม่มีความเสี่ยงเรื่อง StackOverflowError เหมือนวิธี Recursive

# ข้อ 6 การค้นหาคู่จำนวนที่มีผลรวมเท่ากับ k

## 1. คำอธิบายแนวคิดของอัลกอริทึม

โจทย์กำหนดให้อาร์เรย์ A มีสมาชิกเรียงลำดับจากน้อยไปมากแล้ว และไม่มีตัวเลขซ้ำกัน ต้องการหาคู่สมาชิกที่รวมกันได้เท่ากับ k

  อัลกอริทึมที่ 1: Brute Force (findPairBruteForce)

    ใช้วิธีวนลูปซ้อนกัน 2 ชั้น (Nested Loop) เพื่อจับคู่สมาชิกทุกคู่ที่เป็นไปได้ (A[i] และ A[j] โดยที่ i < j) แล้วคำนวณหาผลรวม หากพบคู่ที่ A[i] + A[j] == k จะแสดงผลและคืนค่า true ทันที วิธีนี้เรียบง่ายที่สุดแต่ประมวลผลช้าที่สุด

  อัลกอริทึมที่ 2: Recursive Two-Pointer (findPairRecursive)

    ใช้ประโยชน์จากการที่อาร์เรย์เรียงลำดับมาแล้ว โดยกำหนดตัวชี้ 2 ตำแหน่ง คือ left = 0 (ค่าน้อยที่สุด) และ right = n - 1 (ค่ามากที่สุด)

    Base Case: หาก left >= right แสดงว่าค้นหาจนตัวชี้เดินมาชนกันแล้วไม่พบคู่ ให้คืนค่า false

    Recursive Case: คำนวณ sum = A[left] + A[right]

      ถ้า sum == k: พบคู่คำตอบ ให้แสดงผลและคืนค่า true

      ถ้า sum < k: ผลรวมยังน้อยเกินไป ต้องการให้ผลรวมเพิ่มขึ้น จึงต้องเลื่อนตัวชี้ซ้ายไปทางขวา (left + 1)

      ถ้า sum > k: ผลรวมมากเกินไป ต้องการให้ผลรวมลดลง จึงต้องเลื่อนตัวชี้ขวาไปทางซ้าย (right - 1)

  อัลกอริทึมที่ 3: Binary Search (findPairBinarySearch)

    วนลูปอ่านสมาชิก A[i] ทีละตัว ตั้งแต่ตำแหน่งแรกจนถึงตำแหน่งสุดท้าย
    
    สำหรับสมาชิกแต่ละตัว ให้คำนวณหาค่าคู่สมที่ต้องการคือ target = k - A[i]
    
    ใช้ Binary Search ในการค้นหาค่า $target$ ในช่วงสมาชิกที่เหลืออยู่ (i + 1 ถึง $n - 1) เนื่องจากข้อมูลเรียงลำดับแล้ว ทำให้ค้นหาได้รวดเร็วมาก (O(\log N) ต่อตัว)

## 5. การวิเคราะห์ Time Complexity

  Brute Force: O(N^2)

    เหตุผล: มีการใช้ลูปซ้อนกัน 2 ชั้น ตรวจสอบสมาชิกทุกคู่ที่เป็นไปได้ทั้งหมด หากมี N สมาชิก จะต้องตรวจสอบประมาณ N \times (N-1) / 2 รอบ

  Recursive Two-Pointer: O(N)

    เหตุผล: ตัวชี้ left และ right ขยับเข้าหากันทีละตำแหน่ง โดยจะไม่มีการตรวจสอบสมาชิกตัวเดิมซ้ำ การทำงานสูงสุดจึงเท่ากับจำนวนสมาชิกทั้งหมด N รอบ

  Binary Search: O(N \log N)

    เหตุผล: มีลูปภายนอกทำงาน N รอบ เพื่อดึงสมาชิกมาหาค่าคู่สม และในแต่ละรอบใช้ Binary Search ในการค้นหาซึ่งใช้เวลา O(\log N) เมื่อนำมารวมกันจึงเป็น O(N \log N)

## 6. การวิเคราะห์ Space Complexity

  Brute Force: O(1)

    เหตุผล: ใช้เพียงตัวแปรดรรชนี i และ j ในการวนลูป ไม่มีการจองหน่วยความจำเพิ่มตามขนาดข้อมูล

  Recursive Two-Pointer: O(N)

    เหตุผล: แม้จะไม่ได้สร้างอาร์เรย์ใหม่ แต่การเรียกฟังก์ชันตัวเองซ้ำ (Recursive) จะกินพื้นที่ Call Stack ลึกลงไปสูงสุดเท่ากับจำนวนสมาชิก N ตัว (ใน Worst case)

  Binary Search: O(1)

    เหตุผล: หากใช้ Binary Search แบบวนลูป (Iterative) ตามโค้ดที่ให้ไว้ จะใช้เพียงตัวแปรคงที่ (low, high, mid) ทำให้ใช้พื้นที่เพิ่มเติมเพียง O(1)

## 7. ตารางเปรียบเทียบตามที่โจทย์กำหนด

Space Complexity : O(1)


Recursive Two-Pointer

Time Complexity : O(N \log N)

Space Complexity : O(1)

## 8. งานวิเคราะห์เชิงลึก

1. เหตุใด Two-Pointer จึงใช้ได้เมื่ออาร์เรย์เรียงลำดับแล้ว?
เนื่องจากอาร์เรย์มีคุณสมบัติ ความสม่ำเสมอเชิงเดี่ยว (Monotonic Property) คือ ค่าจะเพิ่มขึ้นจากซ้ายไปขวาเสมอ:

  เมื่อเรานำสมาชิกตัวน้อยสุด (A[left]) มาบวกกับตัวมากสุด (A[right]) แล้วได้ sum < k หมายความว่า A[left] นำไปจับคู่กับสมาชิกตัวใดก็ตามที่เหลืออยู่ในช่วงปัจจุบัน ก็จะไม่มีทางได้ผลรวมถึง k อย่างแน่นอน เพราะ A[right] คือตัวที่มากที่สุดแล้ว การขยับ left ไปทางขวาจึงเป็นหนทางเดียวที่ทำให้ผลรวมเพิ่มขึ้นได้

  ในทางกลับกัน หาก sum > k แสดงว่า A[right] นำไปจับคู่กับตัวใดในอาร์เรย์ก็จะมีค่าเกิน k เสมอ การขยับ right ไปทางซ้ายจึงเป็นหนทางเดียวที่ทำให้ผลรวมลดลง

  คุณสมบัตินี้ทำให้เราสามารถ ตัดสมาชิกที่ไม่ใช่ออกได้ทีละ 1 ตัวในแต่ละขั้นตอน (O(1)) โดยไม่ต้องย้อนกลับไปตรวจสอบคู่ซ้ำ

2. จะเกิดอะไรขึ้นหากนำวิธี Two-Pointer ไปใช้กับอาร์เรย์ที่ยังไม่เรียงลำดับ?
จะทำให้เกิด ข้อผิดพลาดและคำตอบที่ผิดพลาด (False Negatives / Incorrect Result)

  หากอาร์เรย์ไม่เรียงลำดับ ตำแหน่ง A[left + 1] ไม่ได้การันตีว่าจะมากกว่า A[left] และ A[right - 1] ไม่ได้การันตีว่าจะน้อยกว่า A[right]

  เมื่อผลรวม sum < k แล้วโปรแกรมขยับ left ไปทางขวา อาร์เรย์ที่ยังไม่เรียงอาจนำไปเจอค่าที่ น้อยลงกว่าเดิม หรือข้ามตัวเลขที่เป็นคู่คำตอบจริงไป ส่งผลให้อัลกอริทึมข้ามคำตอบถูกต้อง และรายงานว่า "ไม่พบคู่คำตอบ" ทั้งที่มีอยู่นั่นเอง

  2. อัลกอริทึมใดเร็วที่สุดเมื่อข้อมูลมีขนาดเล็ก

  3. อัลกอริทึมใดเหมาะสมที่สุดเมื่อข้อมูลมีขนาดใหญ่

    Algorithm 3 (Binary Search) เหมาะสมที่สุด เนื่องจากทำงานแบบวนลูป (Iterative) ทำให้ไม่กินหน่วยความจำ (Space O(1)) และทำงานได้เสถียรกว่า Algorithm 2 แบบ Recursive ที่อาจทำให้โปรแกรมล่มเมื่อข้อมูลใหญ่มากๆ
    
    
  4. Recursive Algorithm มีข้อจำกัดด้านหน่วยความจำอย่างไร

    ต้องใช้หน่วยความจำประเภท Stack เพื่อเก็บสถานะของฟังก์ชันที่ถูกเรียกซ้อนกัน (Call Stack) หากระดับการเรียกซ้อนลึกเกินไป (เช่น ข้อมูลหลักแสนตัว) จะทำให้หน่วยความจำส่วนนี้เต็ม และเกิด Error (Stack Overflow)
    
  
  5. เหตุใดอัลกอริทึมที่มี Big-O เท่ากันจึงอาจใช้เวลาจริงแตกต่างกัน

    เพราะ Big-O เป็นเพียงการวัด "อัตราการเติบโต" โดยละทิ้งค่าคงที่ (Constant Factors) ทิ้งไป เวลาจริงยังขึ้นอยู่กับปัจจัยอื่น เช่น Overhead ในการเรียกฟังก์ชัน การจัดการแคช (Cache) ของ CPU และกระบวนการของภาษาโปรแกรม

    
  6. การวัดเวลาเพียงครั้งเดียวเพียงพอหรือไม่ เพราะเหตุใด

    ไม่เพียงพอ เพราะการทำงานของ CPU ไม่คงที่ อาจมีโปรแกรมอื่นในระบบแย่งทรัพยากร (Context Switch) หรือความล่าช้าในจังหวะแรกที่รันโค้ด การรันหลายครั้งแล้วหาค่าเฉลี่ย จะช่วยลดความคลาดเคลื่อนและได้ค่าที่สะท้อนความเป็นจริงมากที่สุด
